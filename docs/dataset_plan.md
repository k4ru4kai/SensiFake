# Sensitivity-Stratified Deepfake Benchmark — Dataset Construction Plan

**Goal:** a paired real/synthetic image benchmark where every image carries (a) an authenticity label `real|fake` and (b) a content-sensitivity score, so detectors can be evaluated per sensitivity stratum.

---

## 1. Sensitivity taxonomy

The ICCV 2025 RRDataset uses seven *scenarios* (War & Conflict, Disasters & Accidents, Political & Social Events, Medical & Public Health, Culture & Religion, Labor & Production, Everyday Life) — that is a **topic** axis, not a sensitivity axis. A single axis conflates "what is depicted" with "how damaging a manipulation would be." Use **two orthogonal axes** plus a derived score; that is the defensible design.

### Axis A — Content domain (topic)
| Code | Domain |
|---|---|
| `everyday` | Everyday life, objects, landscapes, food, leisure |
| `commercial` | Products, ads, fashion |
| `portrait` | Non-public-figure people / faces |
| `political` | Politicians, elections, protests, government |
| `conflict` | War, armed conflict, refugees |
| `disaster` | Earthquakes, floods, accidents, casualties |
| `health` | Public health, vaccines, medical scenes |
| `identity` | Religion, ethnicity, culture (depiction-sensitive) |
| `justice` | Crime, courts, policing, evidence-as-image |
| `finance` | Markets, fraud, corporate claims |

### Axis B — Harm potential (the actual sensitivity axis)
Rate independently of domain:

| Code | Level | Definition |
|---|---|---|
| **S0** | Negligible | No plausible harm if fabricated; purely decorative |
| **S1** | Low | Mild misrepresentation; personal embarrassment at most |
| **S2** | Moderate | Consumer/economic deception, non-public identity misuse |
| **S3** | High | Could mislead a substantial public; reputational damage to identifiable people |
| **S4** | Critical | Could cause physical harm, panic, election interference, or violence |

### Derived continuous score
```
sensitivity = 0.5 · domain_risk + 0.3 · harm_level + 0.2 · realism_impact
```
Where `domain_risk ∈ [0,1]` is assigned per Axis-A code by rubric, `harm_level = S/4`, and `realism_impact` ∈ [0,1] is an annotation of how plausible the image looks as documentary evidence. Store both the **ordinal stratum** (S0–S4, used for stratifying results) and the **continuous score** (used for regression / correlation analysis). Report the rubric weights in the paper; do not hide them.

### Annotation rubric (must be pre-registered)
For each image, three independent annotators answer:
1. **Domain** — forced choice over Axis A (single label + optional secondary).
2. **Harm level** — forced choice S0–S4 with the written definitions above shown to them.
3. **Realism impact** — Likert 1–5: "if a viewer believed this image is authentic, how much would it matter?"
4. **Confidence** — Likert 1–5 (used for filtering; drop items with mean confidence < 3).

**Inter-annotator agreement:** report Krippendorff's α for Domain and Harm (ordinal α for Harm). Target α ≥ 0.67; adjudicate disagreements by majority, escalate ties to a fourth annotator. Publish the full rubric and α per stratum — reproducibility is an explicit project objective.

## 2. Source pool (real and fake)

Two strategies; pick one and justify it in the paper.

### Strategy A — Pair-generation (recommended for a *paired* benchmark)
Take **real** images from topic-controlled, openly licensed corpora, then generate the synthetic counterpart with a controlled prompt. This gives you a genuine real↔fake pair per content item, which is exactly what the brief asks for ("pairing real and synthetic images across levels of content sensitivity").

| Role | Source | Notes |
|---|---|---|
| Real images | **MS COCO** | 123k images, structured captions, every-day scenes, permissive licence. Good for `everyday`/`commercial`. |
| Real images | **Open Images v7** | ~9M, very broad topic coverage incl. people, events, scenes; CC-BY. |
| Real images | **Wikimedia Commons** | Key for `political`, `conflict`, `disaster`, `health` — actual documentary/news photography, CC-BY-SA or public domain. |
| Real images | **Reuters / Getty via licensed academic access**, **FactCheck.org / Snopes media galleries** | For high-sensitivity real items; check licence per item, store provenance. |
| Fake images | Generated by you: **Stable Diffusion 3.5 / SDXL, FLUX.1-dev, DALL·E 3, Midjourney v6/v7** | Rebuild the RRDataset generator list; generation prompt derived from the real image's caption. |

For a *paired* item: `(real_i, caption_i) → prompt → fake_i` with identical content domain, then annotate sensitivity **once for the pair** (the sensitivity is a property of the depicted content, not of its authenticity).

### Strategy B — Curate-and-combine (fast, larger, but not paired)
Pull from existing mixed real/fake corpora and re-annotate. Useful for scale, weaker for the paired claim.

| Dataset | Real | Fake | Content coverage | Access |
|---|---|---|---|---|
| **GenImage** | 1,331,167 | 1,350,000 | ImageNet 1000 classes; 8 generators incl. Midjourney, SD1.4/1.5, ADM, GLIDE, BigGAN, VQDM, Wukong | [Homepage](https://genimage-dataset.github.io/) · [GitHub](https://github.com/GenImage-Dataset/GenImage) (Google Drive + Baidu) |
| **ForgeryNet** | 1,438,201 | 1,457,861 | Face-centric, 7 image-level manipulation methods | [GitHub](https://github.com/yinanhe/forgerynet) |
| **DFFD** | 58,703 | 240,336 | Faces, multiple SOTA methods | [project page](http://cvlab.cse.msu.edu/project-ffd.html) |
| **iFakeFaceDB** | — | 87,000 (StyleGAN) | Faces | [GitHub](https://github.com/socialabubi/iFakeFaceDB) |
| **RRDataset** | (paired) | (paired) | **7 real-world scenarios incl. War, Disasters, Health** — closest prior work | [Zenodo](https://zenodo.org/records/14963880) |
| DeepFakeFusion-304K / 399K | mixed | mixed | Merged multi-source faces | [Kaggle](https://www.kaggle.com/datasets/ajaysonicu/deepfakefusion-304k-realfake-faces) |

**Recommended:** Strategy A for the sensitivity-stratified core (target 3,000–6,000 paired items, ≥300 per S-stratum per domain), plus Strategy B (GenImage subset) as a large-scale generality check. Cite GenImage's own numbers: 2,681,167 images split into 1,331,167 real / 1,350,000 fake ([source](https://doi.org/10.48550/arxiv.2306.08571)).

## 3. Schema

One row per image, Parquet + JSONL mirrors.

```json
{
  "image_id": "seg_000123_r",
  "pair_id": "pair_000123",
  "path": "images/everyday/S1/seg_000123_r.webp",
  "label": "real",                    // real | fake
  "label_bin": 0,
  "domain": "everyday",               // Axis A
  "domain_risk": 0.15,
  "harm_level": 1,                    // Axis B, 0-4
  "realism_impact": 2,                // 1-5
  "sensitivity_score": 0.0,           // derived, continuous
  "sensitivity_stratum": "S1",        // S0-S4
  "generator": null,                  // "sd3.5-large","flux.1-dev",... for fakes
  "prompt": null,                     // generation prompt for fakes
  "source_dataset": "coco",           // provenance
  "source_url": "http://images.cocodataset.org/...",
  "license": "CC-BY-4.0",
  "width": 640, "height": 480,
  "split": "train",                   // train | val | test
  "annotators": ["a01","a02","a03"],
  "annotator_confidence": 4.2,
  "krippendorff_alpha_domain": 0.81,  // at group level; per-item flag optional
  "added_perturbations": []           // transmission / re-digitization variants
}
```

**Directory layout**
```
dataset/
├── README.md                # dataset card w/ YAML front-matter
├── metadata/
│   ├── manifest.parquet     # ← the master table above
│   ├── manifest.jsonl
│   ├── taxonomy.json        # frozen rubric + weights
│   ├── annotation_sheet.csv
│   └── agreement_report.json
├── images/
│   ├── real/{domain}/{stratum}/{id}.webp
│   └── fake/{generator}/{domain}/{stratum}/{id}.webp
└── splits/{train,val,test}.txt   # pair-disjoint, not image-disjoint
```

**Critical split rule:** split by `pair_id`, never by `image_id`. Otherwise the real half of a pair lands in train and its fake twin in test, and your accuracy is meaningless. Also stratify splits so every `(stratum × domain)` cell appears in val and test.

## 4. Annotation pipeline (make it *systematic and reproducible*, per the brief)

1. **Pre-register** the rubric (`taxonomy.json` committed before any annotation starts). Freeze a hash of it.
2. **Pilot** on 200 images; measure α; revise rubric **once**; re-freeze.
3. **Main annotation** in a tool that logs per-annotator timestamps: Label Studio, Prodigy, or a small custom streamlit app.
4. **Automated pre-scoring** as a second signal, not a replacement for humans:
   - **LlavaGuard** — VLM safeguard outputting `Safe|Unsafe` + **safety category** + rationale, explicitly built for dataset annotation ([GitHub](https://github.com/ml-research/llavaguard), [paper](https://arxiv.org/abs/2406.05113)). Best fit for Axis B at scale.
   - LAION **CLIP-based NSFW/NSFW-detector** for the explicit-content slice ([reference implementation](https://github.com/backblaze-b2-samples/clip-nsfw-image-moderation)).
   - CLIP zero-shot offensiveness probing — reported at 96.3 ± 1.1% accuracy on the SMID moral-stimulus benchmark ([paper](https://ar5iv.labs.arxiv.org/html/2110.04222)); use as an S3/S4 triage signal.
   - Report human↔model agreement; do **not** let model scores overwrite human labels — keep them as `auto_harm_score` and `auto_categories`.
5. **Ethics gate:** any image depicting real identifiable victims, casualties, or atrocities → requires a documented licence/consent record or is dropped. Sponsor this explicitly; it's the main reviewer objection to this project.

## 5. Benchmarking a detector on it

Per the brief, run one or more pre-trained detectors and report performance **per sensitivity stratum**.

- Candidate detectors (as evaluated in RRDataset): CNN artifact detectors (ResNet-50, CNNDetection, Gram-Net), frequency methods (FreqNet, DFFreq), reconstruction/attribution methods (DIRE, DNF, AEROBLADE), CLIP-based (CLIPDetection, AIDE, SAFE, UniFD).
- Report **R.Acc** (real accuracy) and **F.Acc** (fake accuracy) separately, not just overall accuracy — AIGIBench shows overall accuracy hides the real trade-off ([paper](https://papers.nips.cc/paper_files/paper/2025/file/fb693c67f61e5321746ffce8b6fdd2d0-Paper-Datasets_and_Benchmarks_Track.pdf)).
- **New metric — propose one.** A natural, defensible choice:

```
Sensitivity-Weighted Error  (SWE) = Σ w(s_i) · 1[ŷ_i ≠ y_i]  /  Σ w(s_i)
   with  w(s) = 1 + λ·s ,  λ configurable (report λ=1 and λ=3)
```
Plus a **High-Stakes Recall** at fixed low FPR on the S3+S4 strata, and a calibration curve of F.Acc vs. sensitivity stratum. Report the Pearson correlation between `sensitivity_score` and per-image detection difficulty — that is your headline plot.

**Reference point for the write-up:** on RRDataset (which includes War, Disasters, Political, Health scenarios), no detector exceeded **89.59%** accuracy, and 192 human participants scored **59.52%** on special/high-stakes scenarios vs. **69.17%** on everyday scenarios — with AI-image accuracy collapsing to **39.64%** vs. **58.29%**. That is direct evidence the sensitivity dimension is real and measurable ([ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Li_Bridging_the_Gap_Between_Ideal_and_Real-world_Evaluation_Benchmarking_AI-Generated_ICCV_2025_paper.pdf)).

## 6. Deliverables & timeline

| Deliverable | Content |
|---|---|
| **D1. Taxonomy + rubric** | `taxonomy.json`, frozen, with weights and α targets |
| **D2. Dataset** | paired real/fake, `manifest.parquet`, images, splits |
| **D3. Dataset card** | HF-style README with YAML, provenance, licences, ethics statement, limitations |
| **D4. Benchmark results** | per-stratum tables for ≥1 detector, SWE + High-Stakes Recall, sensitivity-vs-difficulty correlation |
| **D5. Reproducibility kit** | generation prompts, annotation logs, agreement report, scripts |

Suggested sequence: taxonomy (wk 1–2) → source clearance + generation (wk 2–4) → pilot annotation + α (wk 4–5) → main annotation (wk 5–8) → dataset card + freeze (wk 8–9) → benchmarking (wk 9–11) → write-up (wk 11–13).

## 7. Reviewer objections to pre-empt

1. **"This is just RRDataset."** → Differentiate: RRDataset has *scenario* labels and robustness axes; you have a **two-axis sensitivity rubric plus a continuous sensitivity score** and a **paired-construction** methodology. Report RRDataset as a baseline and cite it ([Zenodo](https://zenodo.org/records/14963880)).
2. **"Sensitivity is subjective."** → Pre-registered rubric, 3 annotators, ordinal Krippendorff's α, sensitivity analyses at λ=1 and λ=3.
3. **"Ethics."** → Explicit curation gate, licence tracking, no generated atrocity imagery of real identifiable people, IRB/ethics statement.
4. **"Real/fake not truly paired."** → Define pairing precisely (same caption + domain), and report how often pairing fails to preserve domain.
5. **"No licence clarity."** → One column per file, and a `LICENSE_AUDIT.md`.
